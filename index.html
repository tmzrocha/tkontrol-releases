Why TKontrolPor que o TKontrol

Built for clusters where a wrong click is expensivePensado para clusters onde um clique errado custa caro

Made for AKSFeito para o AKS

Finds kubelogin and the Azure CLI even outside PATH, discovers the AKS clusters of your subscription and explains a failed sign-in by its cause: no az login, expired login, Conditional Access or a missing tool.

Encontra o kubelogin e o Azure CLI mesmo fora do PATH, descobre os clusters AKS da sua assinatura e explica um login que falha pela causa: sem az login, login expirado, Acesso Condicional ou ferramenta ausente.

Careful in productionCuidadoso em produção

Operations check your RBAC permission first and can be simulated on the server (dry run). Deletes, drains and any change on a production cluster ask for confirmation in a second step, with a PRD badge.

As operações conferem primeiro a sua permissão no RBAC e podem ser simuladas no servidor (dry run). Excluir, drenar e qualquer alteração num cluster de produção pedem confirmação numa segunda etapa, com o selo PRD.

A terminal with rulesUm terminal com regras

The integrated kubectl is bound to the selected cluster. On a production cluster, a command that may change it runs only after you type the cluster's name. Every command is audited.

O kubectl integrado fica preso ao cluster selecionado. Num cluster de produção, um comando que pode alterá-lo só roda depois de você digitar o nome do cluster. Todo comando é auditado.

Honest dataDados honestos

A count that could not be read shows as "not read", not as zero. Without the Metrics API, TKontrol says usage is unavailable instead of making up numbers.

Uma contagem que não pôde ser lida aparece como "não lido", e não como zero. Sem a Metrics API, o TKontrol diz que o uso está indisponível, em vez de inventar números.

Fast on large clustersRápido em clusters grandes

When your permissions allow watching the cluster, a watch cache keeps the lists live without polling, and the global search reads names from it.

Quando as suas permissões deixam acompanhar o cluster (watch), um cache mantém as listas ao vivo sem consultas repetidas, e a busca global lê os nomes dele.

Read-only when you need itSomente leitura quando precisar

Mark a cluster read-only in TKontrol and the backend refuses every change to it, the terminal included. Actions and file copies go to a local audit log.

Marque um cluster como somente leitura no TKontrol e o backend recusa qualquer alteração nele, inclusive pelo terminal. Ações e cópias de arquivos vão para um log de auditoria local.

Security and privacySegurança e privacidade

Your credentials stay on your machineAs suas credenciais ficam na sua máquina

  • No privilege elevation. Every call to a cluster uses the credentials of the imported context; TKontrol has no administrative identity of its own.
  • Sem elevação de privilégio. Toda chamada a um cluster usa as credenciais do contexto importado; o TKontrol não tem identidade administrativa própria.
  • Encrypted at rest. Credentials use AES-256-GCM and are never shown again or written to logs.
  • Criptografadas. As credenciais usam AES-256-GCM e nunca são mostradas de novo nem gravadas em logs.
  • Local only. The backend listens on a random port of 127.0.0.1, protected by a session token created at each start.
  • Só local. O backend escuta numa porta aleatória de 127.0.0.1, protegido por um token de sessão criado a cada abertura.
  • Secrets stay hidden. Lists, details and YAML never receive Secret values. You can reveal one key at a time, if RBAC allows; it hides again after 30 seconds.
  • Secrets ficam ocultos. Listas, detalhes e YAML nunca recebem os valores dos Secrets. Você pode revelar uma chave por vez, se o RBAC permitir; ela some de novo depois de 30 segundos.

No telemetry. TKontrol only connects to:Sem telemetria. O TKontrol só se conecta a:

  • your clusters;
  • Azure Resource Manager and Microsoft sign-in, when you discover AKS clusters, open the Azure details or run the Azure checks;
  • GitHub Releases, for the update check, which you can turn off;
  • the Trivy vulnerability database and your image registries, in a Security Center scan;
  • the Kubeconform schemas, in an Upgrade Advisor scan.
  • os seus clusters;
  • o Azure Resource Manager e o login da Microsoft, quando você descobre clusters AKS, abre os Detalhes do Azure ou faz as verificações do Azure;
  • o GitHub Releases, para procurar atualizações, o que pode ser desligado;
  • a base de vulnerabilidades do Trivy e os seus registries de imagens, numa análise do Security Center;
  • os schemas do Kubeconform, numa análise do Upgrade Advisor.

No usage data, crash report or identifier is collected or sent. Updates are only installed after you confirm, and only when signed with the project's updater key.

Nenhum dado de uso, relatório de falha ou identificador é coletado ou enviado. Uma atualização só é instalada depois que você confirma, e só se estiver assinada com a chave do atualizador do projeto.

Up and running in a few minutesFuncionando em poucos minutos

  1. Download the installer from the latest release.
  2. Baixe o instalador da última versão.
  3. Run it. The installers are not Authenticode-signed yet, so SmartScreen may say "Windows protected your PC": choose More info → Run anyway.
  4. Execute. Os instaladores ainda não têm assinatura Authenticode, então o SmartScreen pode dizer "O Windows protegeu o computador": escolha Mais informações → Executar assim mesmo.
  5. Open TKontrol. To look around without a cluster, choose Explore Demo Mode in the tray icon menu.
  6. Abra o TKontrol. Para conhecer sem um cluster, escolha Explorar o Modo Demo no menu do ícone da bandeja.
  7. On the Clusters page, choose Import kubeconfig: pick contexts from ~/.kube/config, paste a kubeconfig or import the AKS clusters of your subscription.
  8. Na tela Clusters, escolha Importar kubeconfig: escolha contextos do ~/.kube/config, cole um kubeconfig ou importe os clusters AKS da sua assinatura.

FAQ

QuestionsPerguntas

Does TKontrol install anything in my clusters?O TKontrol instala alguma coisa nos meus clusters?

No. It talks to the API server with your kubeconfig. The scanners of Cluster Health, Security Center and Upgrade Advisor ship inside the installer and run on your machine.

Não. Ele fala com o API server usando o seu kubeconfig. Os scanners do Cluster Health, do Security Center e do Upgrade Advisor vêm no instalador e rodam na sua máquina.

Does it only work with AKS?Só funciona com AKS?

It is a desktop for Kubernetes clusters, built around AKS (Entra ID sign-in, Azure details, Windows node pools). It talks to your clusters with your own kubeconfig; the Azure-specific screens only apply to AKS.

É um desktop para clusters Kubernetes, pensado para o AKS (login com Entra ID, Detalhes do Azure, node pools Windows). Ele acessa os clusters com o seu próprio kubeconfig; as telas específicas do Azure só valem para o AKS.

Can I try it without a cluster?Dá para experimentar sem um cluster?

Yes. Choose Explore Demo Mode in the tray icon menu. It shows simulated data only, and the app returns to your clusters when you leave it.

Sim. Escolha Explorar o Modo Demo no menu do ícone da bandeja. Ele mostra só dados simulados, e o app volta aos seus clusters quando você sai.

Why does Windows warn me when I install it?Por que o Windows avisa quando eu instalo?

The installers are not Authenticode-signed yet, so SmartScreen shows "Windows protected your PC". Check the file against SHA256SUMS.txt, then choose More info → Run anyway.

Os instaladores ainda não têm assinatura Authenticode, então o SmartScreen mostra "O Windows protegeu o computador". Confira o arquivo com o SHA256SUMS.txt e escolha Mais informações → Executar assim mesmo.

How do updates work?Como funcionam as atualizações?

About 20 seconds after opening, TKontrol downloads latest.json from GitHub and sends nothing about you or your machine. It always asks before installing. Turn it off in Settings → Updates, or for an organization with TKONTROL_NO_UPDATE_CHECK=1.

Cerca de 20 segundos depois de abrir, o TKontrol baixa o latest.json do GitHub e não envia nada sobre você ou a sua máquina. Ele sempre pergunta antes de instalar. Desligue em Preferências → Atualizações, ou para uma organização com TKONTROL_NO_UPDATE_CHECK=1.

Does it work behind a corporate proxy?Funciona atrás de um proxy corporativo?

Yes. Set HTTPS_PROXY and NO_PROXY as Windows environment variables; a proxy-url in the kubeconfig is honored too. Calls to Azure and GitHub trust the Windows certificate store, where IT installs the corporate CA.

Sim. Defina HTTPS_PROXY e NO_PROXY nas variáveis de ambiente do Windows; o proxy-url do kubeconfig também é respeitado. As chamadas ao Azure e ao GitHub confiam no repositório de certificados do Windows, onde a TI instala a CA corporativa.

Is the source code available?O código-fonte está disponível?

Not yet. The releases repository hosts the installers and the files the in-app updater reads. No license has been published yet; until then, all rights are reserved by the author. The bundled scanners keep their own licenses.

Ainda não. O repositório de releases guarda os instaladores e os arquivos que o atualizador do app lê. Nenhuma licença foi publicada ainda; até lá, todos os direitos são reservados ao autor. Os scanners empacotados mantêm as próprias licenças.

Where do I report a problem?Onde relato um problema?

Open an issue on GitHub with the TKontrol version, what you did and what happened. Never attach a kubeconfig, tokens, tkontrol.db or secret.key.

Abra uma issue no GitHub com a versão do TKontrol, o que você fez e o que aconteceu. Nunca anexe kubeconfig, tokens, tkontrol.db ou secret.key.
